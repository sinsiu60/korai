# 현태의 시골버스 — Claude Code 작업 규칙

이 폴더는 「현태의 시골버스」 HTML 버전(완성본)과, 이것을 Unity로 옮기는 프로젝트의 인계 자료다.
claude.ai 대화에서 시작한 작업을 이어받는 것이므로, **작업 전에 아래 순서로 반드시 읽는다.**

1. `HANDOFF.md` — 지금까지 한 일, 결정 사항, 현재 단계, 다음에 할 일 (가장 먼저)
2. `docs/00-spec.md` — 사용자가 쓴 원본 작업 지시서 (수정 금지)
3. `docs/01-html-analysis.md` — 1단계 결과: HTML 코드 전체 분석 (기능·물리·수치·경영 구조, 옮김/다시 짬 구분)
4. 필요할 때 `src/*.js` — HTML 원본 코드 (Unity로 옮길 로직의 기준 구현)

## 작업 규칙 (사용자 지시서에서 가져옴 — 반드시 지킬 것)

- 지시서의 단계를 **순서대로** 진행한다. 각 단계가 끝나면 **멈추고** "결과 요약 + 사용자가 테스트할 방법"을 알려 준다. 사용자가 OK해야 다음 단계로 간다.
- 단계마다 git 커밋.
- 모르는 것(라이브러리 최신 상태, API, 패키지 버전, 라이선스)은 **추측하지 말고 확인**한 뒤 진행한다. 확인한 출처를 보고에 적는다.
- 조향각, FFB 세기, 기어비 등 **모든 수치는 하드코딩 금지** — ScriptableObject나 설정 파일로 빼서 사용자가 조절할 수 있게 한다.
- 테스트하지 못한 것은 테스트했다고 말하지 않는다. "확인함 / 확인 못 함"을 나눠서 보고한다.
- Unity 작업은 사용자 PC에서 하므로, 코드를 고친 뒤 가능하면 Unity를 batchmode로 실행해 **컴파일 오류가 없는지 직접 확인**하고 보고한다 (명령줄 옵션은 설치된 버전 문서로 확인 후 사용).

## 사용자와 소통

- 한국어로 답한다. 제목·표·글머리표로 정리하고, 긴 줄글은 피한다.
- 정해진 작업이면 되묻지 말고 끝까지 한다. 진짜로 사용자가 정해야 하는 것만 묻는다.
- 단계 보고는 짧게: 무엇을 했는지, 어떻게 테스트하는지, 결정이 필요한 것.

## 게임 세계관 (현태 시리즈 공통 — 게임 안 텍스트에 적용)

- B급 감성이지만 버스 시뮬레이터로서는 **본격적**이어야 한다.
- 주인공 **현태**: 말투 "~씁니다 / ~씹시오", 대답은 "예." / 볶음밥은 2인분부터(1인분에 계란 2개) / 별명 '무현태'(무에타이).
- 게임 시작 시 개발사 로고 **"시우 공방"**(SIWOO WORKSHOP)을 띄운다.
- **송창희는 절대 등장시키지 않는다** (본인 요청).
- 배경은 계란리와 무관한 새 시골 동네 (HTML 버전은 "구불군"). 회사 이름 「현태운수」.

## 폴더

| 경로 | 내용 |
|---|---|
| `index.html` | HTML 버전 실행 파일 (브라우저로 열기, 인터넷 필요 — three.js CDN) |
| `src/` | HTML 원본 소스 (p1~p5 js + head.html, `python build.py`로 index.html 생성) |
| `docs/` | 지시서, 단계별 결과 문서 |
| `HANDOFF.md` | 인계 문서 — 단계가 끝날 때마다 "현재 상태"와 "결정 기록"을 갱신할 것 |

Unity 프로젝트 자체는 이 저장소(korai)가 아니라 **별도 저장소**에 만든다 (HANDOFF.md 참고).
