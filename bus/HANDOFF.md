## 3. 결정 기록 (시간순)

### HTML 버전 만들 때 사용자가 정한 것

| 질문 | 사용자 답 |
|---|---|
| 시점 | 3D 운전석 1인칭 |
| 변속 | 자동 변속 + 실감 기능 (도어 브레이크, 주차 브레이크, 닐링, 깜빡이 자동 취소 등) |
| 게임 구조 | 운행 + 회사 경영 |
| 배경 | 새로운 시골 동네 (계란리와 무관) → "구불군" |

### HTML 플레이 후 사용자 피드백 → 반영함

| 피드백 | 반영 내용 |
|---|---|
| 패드 키를 **유로트럭 시뮬레이터 2 방식**으로 | 십자 ←/→ 깜빡이, **LB 누른 채 오른쪽 스틱 ↑/↓ 기어 올림/내림**, X 전조등, 왼쪽 스틱 조향(묵직하게, 속도 감응, 비선형) |
| 앞으로 갈 때 버스가 덜덜 떨림 | 원인: 운전석 카메라가 버스 위치를 한 프레임 늦게 따라감 → 같은 프레임 위치 사용으로 수정. **Unity에서도 카메라는 차량 물리 갱신 후(LateUpdate / 보간된 Rigidbody 위치) 따라가게 할 것** |

### Unity 이전 지시서 (`docs/00-spec.md`)

- 사용자가 직접 쓴 7단계 지시서. 이전 이유: 맵이 단조로움(평지 순환도로), 브라우저는 포스피드백 불가.
- 가장 중요하다고 한 단계: **4단계 시골 읍내 맵** (맵 설계도를 먼저 보여 주고 OK 받은 뒤 제작).

### 1단계에서 정리된 사실 (사용자에게 보고함)

- 지시서 6단계의 **"기사 고용"은 HTML에 없는 신규 기능**이다. 이전이 아니라 새로 설계해야 함.
- HTML 물리는 운동학 자전거 모델(질량·경사·노면 없음) → Unity에서는 다시 짜야 함. 변속·제동 수식과 수치는 재사용.
- HTML 화면 핸들은 최대 ±249°라 900° 휠과 1:1 불가 → 핸들 각도와 앞바퀴 각도를 조향비로 분리해야 함 (900° 기준 약 12.7:1이면 앞바퀴 ±35°).

## 4. HTML 버전에서 겪은 문제와 교훈 (Unity에서 같은 실수 방지)

| 문제 | 교훈 |
|---|---|
| 마지막 정류장(종점)을 놓치면 운행이 끝나지 않고 버스가 경로 끝을 넘어감 | 운행 종료는 "종점 승하차 완료" 외에 "다음 정류장 없음" / "경로 끝 도달"에서도 반드시 처리 |
| 같은 도로를 두 번 지나는 노선(왕복)에서 정류장 위치를 잘못 찾음 | 정류장은 노선 순서대로, 직전 정류장 이후 구간에서만 찾을 것 |
| 회전 교차로처럼 급커브에서 자동 주행 테스트봇이 경로를 이탈 | 경로 추종 lookahead는 곡률에 따라 줄일 것 |
| 정차 칸에 대지 않고 문 열면 승객이 안 타는데 이유를 몰라 답답함 | 정차 판정 실패 시 "표지판에 더 가까이 / 오른쪽에 붙여" 같은 안내를 띄울 것 |
| 키보드로 메뉴 조작 불가였음 | 메뉴는 처음부터 키보드·패드·마우스 모두 지원 |
| 시간표보다 일찍 출발 벌금이 너무 빡빡했음 | 30초 여유 + HUD에 "출발까지" 카운트다운 |
| 승급 비용이 너무 높아 지루함 | 1번 노선 ★5 1회 ≈ 순이익 30만 원 기준으로 노선 2~7백만, 버스 4백만~2.5천만으로 낮춤 |
