# 와트 팩토리 · 시우 공방

태블릿(iPad/안드로이드 태블릿) 브라우저에서 터치로 플레이하는 2D 공장 자동화 게임입니다. (레퍼런스: shapez, Factorio)
전력망 관리가 이 게임의 핵심 차별점입니다(4단계).

> "와트 팩토리"는 임시 제목입니다. `index.html`의 `<title>`과 `.menu-title`만 바꾸면 됩니다.

## 실행 방법
빌드 과정 없이 정적 파일만으로 동작합니다. 다만 브라우저 보안 정책 때문에 `index.html`을 **파일로 직접 열면(file://)** `data/*.json`을 읽지 못하므로, 간단한 웹 서버로 띄워야 합니다.

```bash
cd factory
python3 -m http.server 8000      # 또는 npx serve .
```

- PC: `http://localhost:8000`
- 태블릿: PC와 같은 Wi-Fi에서 `http://<PC의 IP>:8000` 접속 (예: `http://192.168.0.12:8000`)
- 또는 GitHub Pages에 올리면 주소만으로 바로 플레이할 수 있습니다.
- iPad 사파리에서 "공유 → 홈 화면에 추가"를 하면 주소창 없이 전체 화면으로 실행됩니다.

Phaser 3.80.1은 `lib/phaser.min.js`로 포함되어 있어 인터넷 연결 없이도 실행됩니다(MIT 라이선스, `lib/PHASER_LICENSE.md`).

### 개발/테스트용 주소 옵션
| 옵션 | 설명 |
|---|---|
| `?skiplogo=1` | 시작 로고 생략 |

| `?stress=items` | 맵 가장자리 고리 컨베이어 4줄에 아이템 약 880개를 흘려 성능 확인 |

## 조작 (터치)
| 동작 | 결과 |
|---|---|
| 한 손가락 드래그 | 맵 이동 (손을 빠르게 떼면 관성 이동) |
| 두 손가락 핀치 | 확대/축소 (두 손가락으로 끌면 이동도 됨) |
| 하단 툴바에서 건물 선택 → 격자 탭 | 배치 (손가락을 대고 있으면 초록/빨강 미리보기) |
| 컨베이어 선택 → 드래그 | 지나간 칸에 연속 설치, 드래그 방향으로 자동 회전 |
| 건물 탭 | 정보 패널 (상태·재료·진행도, 조립기 레시피 선택, PLC 설정, 정지/켜기) |
| 건물 길게 누르기 (약 0.5초) | 빨간 링이 다 차면 삭제 |
| 오른쪽 회전 버튼 | 도구 선택 중: 다음 건물 방향 / 건물 선택 중: 그 건물 회전 |
| 상단 ⚡ 게이지 탭 | 트립된 차단기 재투입 |
| 오른쪽 위 목표 카드 탭 | 해금 트리 보기 |

PC에서는 마우스 드래그 = 손가락 드래그, 휠 = 줌으로 테스트할 수 있습니다.

## 플레이 흐름
1. **전기 연결**: 납품소는 기본 전력 400kW를 냅니다. 납품소 바로 옆에 **전신주**를 세우면 파란 공급 영역 안의 기계에 전기가 들어갑니다. 전신주끼리는 8칸 안이면 자동으로 전선이 이어져 하나의 전력망이 됩니다.
2. **채굴 → 납품**: 광석 지대에 채굴기를 놓고(광석 칸이 많을수록 빠름), 화살표 앞에서 납품소까지 컨베이어를 드래그합니다.
3. **목표 달성 → 해금**: 오른쪽 위 목표(예: 철광석 30개)를 채우면 제련소·분배기·발전기·조립기·창고·PLC가 차례로 열립니다.
4. **전력 관리 (핵심)**: 기계를 늘리면 수요가 공급을 넘습니다.
   - 수요 > 공급 → 같은 전력망의 모든 기계가 `공급/수요` 비율로 느려집니다.
   - 과부하가 **6초** 이어지면 **차단기 트립** → 그 전력망 전체 정지(전선이 빨갛게 변함). 상단 게이지를 탭해 재투입하세요. 원인을 해결하지 않으면 다시 내려갑니다.
   - **발전기**(+600kW)는 석탄을 태웁니다. 납품소 전력을 먼저 쓰고 모자란 만큼만 연료를 씁니다.
5. **PLC 자동 제어**: PLC를 탭 → 센서 `지정` → 건물 탭, 대상 `지정` → 건물 탭, 조건/동작 선택.
   - 예) 센서=창고, 조건=가득 참, 동작=참이면 대상 끄기, 대상=채굴기 → 창고가 차면 채굴기 정지
   - 예) 센서=전신주, 조건=전력 부족, 대상=조립기 → 과부하 때 조립기를 꺼서 트립 예방(부하 차단)
6. 모터 30개를 납품하면 **공장 완성**!

### 물류 규칙
- 컨베이어 한 칸에 아이템이 최대 2~3개(간격 0.5칸). 앞이 막히면 줄줄이 멈춥니다.
- 컨베이어 옆구리로 다른 컨베이어를 대면 합류합니다. 뒤에서 들어오는 줄이 없으면 자동으로 곡선이 됩니다.
- 분배기: 뒤에서 받아 앞·왼쪽·오른쪽으로 번갈아. 합류기: 뒤·왼쪽·오른쪽에서 돌아가며 받아 앞으로.
- 기계(제련소·조립기·창고)는 화살표(출력) 면을 뺀 모든 면으로 재료를 받습니다. 제련소는 들어온 광석에 맞춰 레시피가 자동 선택됩니다.

## 저장
- 30초마다, 그리고 앱이 백그라운드로 갈 때(홈 버튼, 탭 전환) 자동 저장됩니다. ☰ 버튼의 초록 점이 깜빡이면 저장된 것입니다.
- 시작 메뉴의 **이어하기**로 계속합니다. 메뉴 → 지금 저장도 가능합니다.
- 저장/불러오기는 모두 try/catch로 감싸 있어, 시크릿 모드·저장 공간 부족·깨진 저장 데이터에서도 게임은 멈추지 않습니다(안내만 표시).

## 데이터 파일 (코드 수정 없이 밸런스 조절)
| 파일 | 내용 |
|---|---|
| `data/buildings.json` | 건물 크기, 소비/공급 전력(kW), 채굴 시간, 창고 용량, 전신주 연결 거리·공급 반경, 연료, `_power.tripSeconds`(트립까지 시간) |
| `data/items.json` | 아이템 이름, 색, 아이콘 모양 |
| `data/recipes.json` | 레시피: 기계, 입력 아이템/수량, 출력, 가공 시간 |
| `data/tech.json` | 해금 트리: 시작 해금, 목표(누적 납품 수량), 선행 목표, 해금 내용 |
| `data/map.json` | 맵 크기, 광석 지대(철·구리·석탄) 개수/크기 |

## 폴더 구조
```
factory/
├─ index.html            # 진입점 (스크립트 순서대로 로드)
├─ css/style.css         # HUD 스타일 (버튼 최소 48px, 안전 영역 대응)
├─ lib/phaser.min.js     # Phaser 3.80.1
├─ data/                 # 게임 데이터 (위 표)
└─ js/
   ├─ util.js            # 상수(TILE, 방향), 시드 난수
   ├─ registry.js        # JSON → 아이템 번호, 레시피 조회, 해금 상태
   ├─ grid.js            # 격자: 광석 지대 생성, 건물 점유 배열
   ├─ art.js             # 도형으로 그린 타일·건물·아이템·로고
   ├─ buildings.js       # 배치/회전/삭제, 겹침 검사
   ├─ conveyor.js        # 컨베이어 슬롯 구조, 분배기·합류기, 아이템 그리기
   ├─ machines.js        # 아이템 주고받기 규칙, 채굴기·제련소·조립기·창고·납품소
   ├─ power.js           # 전력망 구성, 효율 저하, 과부하·차단기 트립
   ├─ plc.js             # PLC 조건 판단과 ON/OFF 제어
   ├─ tech.js            # 납품 목표와 해금
   ├─ save.js            # localStorage 저장/불러오기
   ├─ input.js           # 터치(이동·핀치·탭·길게누르기·드래그 설치), 카메라
   ├─ ui.js              # 툴바, 게이지, 목표, 정보 패널, 모달, 메뉴
   ├─ sound.js           # Web Audio 효과음
   ├─ perf.js            # 성능 테스트 도우미
   ├─ main.js            # Phaser 생성, 레티나/화면 회전 대응
   └─ scenes/            # boot(데이터 로드) → logo(시우 공방) → title(메뉴) → game
```

## 성능
- 아이템은 개별 객체가 아니라 컨베이어 칸마다 `{아이템번호, 위치}` 슬롯 배열로 관리하고, 하류→상류 순서로 1/60초 고정 간격 시뮬레이션합니다.
- 화면에는 카메라에 보이는 아이템만, 같은 텍스처의 이미지 풀을 재사용해 한 번에 그립니다.
- `?stress=items`(아이템 약 880개가 계속 흐름)로 측정한 메인 스레드 시간(헤드리스 크롬, GPU 없음): 시뮬레이션 0.2~0.3ms/스텝, 프레임 전체 평균 3~4.5ms (60fps 예산 16.6ms).
